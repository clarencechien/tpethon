# 內湖完整 BRT：捷運施工過渡期實驗

互動頁：https://clarencechien.github.io/tpethon/brt.html

完整 BRT **可能**以較少道路空間運更多人，但不能由國外案例推得內湖固定的減塞百分比。此版提供可重現、可否證的條件實驗：挪一條車道後，轉乘、站點、車隊與成長是否仍能讓道路和乘客都疏解？它不是工程設計或內湖交通預測。

## 查證的研究依據

- [運輸表現](https://github.com/ITDP/the-online-brt-planning-guide/blob/9d3057044d8201a84d7c35fa67789e4cbcf099a4/guide/02-why-brt/04-performance.manu)：歷史觀測尖峰單向載客量，曼谷約 1,200、廣州約 27,400 人／時／方向。廣州站區有超車能力。這些不是現況、容量上限或道路減塞率，不能移植到只有單停靠位、無超車站的走廊。指南亦提醒站點占用超過約 40% 可能產生公車排隊，模型超過時顯示警示。

## 模型與參數

四情境：施工前參考、僅施工、施工＋混流加班車、施工＋完整 BRT。三個施工情境使用同年的需求；「施工前」僅為同需求下移除施工的反事實參考，不是歷史實測。

- 道路為兩條抽象通道，不代表某座橋或街道。主要通道原有車道扣除施工占道，再扣 BRT 專用道；須至少保留一條一般車道，否則回報配置不可行。車道容量是已扣除其他交通後給本批旅次的容量。外圍容量與改道比例另設，沒有自動路網分配。
- 基期私車使用者與既有公車乘客分開給定；每年分別乘 `(1 + 年成長率)^年數`。只有主通道私車使用者按轉乘率改搭公車。每人旅次只計一次，外圍旅次不因政策消失。既有捷運 OD 未加入，因為它既不是開車族，也不是剩餘運能。
- 實測模式採單一 VD × 方向的至少三個完整參考工作日相對型態；讀取 GitHub `data/weeks/profiles.json`，校驗索引 SHA-256、bytes 和日期。每個抽樣值持有 15 分鐘後正規化，是需求分布假設；原始 VD 統計區間未確認，不能直接加總成尖峰流量，也不表示壅塞時未受限的到達需求。公車乘客借用相同型態亦是假設。
- 車道採確定性流體排隊，30 秒步長，將超出容量的流量保留到下一步。混流公車每次發車計入主通道 PCU；BRT 公車在已扣除的一條專用道服務。最大追蹤至需求結束後 8 小時；仍未疏解的量另列，排隊積分為下界。
- 乘客按到達順序 FIFO 上車。每班容量為 `floor(額定載客 × 可用載客率)`，有限車隊須待同車循環返回後才能發車。有效班距至少為停靠＋清空時間，向上取到 30 秒格點。每步起點批次到達，使短候車時間帶有約一個步長的離散誤差。
- BRT 單程時間＝里程／行駛速度＋站數×停靠時間＋路口數×剩餘號誌延誤；循環＝雙向單程＋折返恢復＋駕駛休息。班表需車＝`ceil(循環／有效班距)`，另加向上取整的備車。可出勤車隊輸入不含備車。這不是完整駕駛排班、法規休息合規或車庫配置規劃。
- 站點單停靠位、無超車。40% 占用警示是指南的規劃篩檢，並非精確崩潰門檻。模型沒有隨機停站時間、站間公車回堵、信號相位或路口衝突。混流公車採使用者提供的固定循環時間，未由道路排隊反饋循環；混流與 BRT 的完整時間利益不能據此估計。
- 所有年度保持相同道路與班表配置。模擬第 0 至 N−1 年；第 N 年只是使用者假設的捷運接續里程碑，不是官方通車日期，尚未模擬通車後運能。

## 如何讀結果

道路排隊 PCU·時是小客車當量積分；乘客候車人·時是另一種單位，兩者不可直接相加。主通道平均排隊分也不是全程旅行時間。候車平均和 P95 只對已上車者計算，未上車者必須一起看。

轉乘掃描以 10 個百分點為格距，只有兩個情境道路和乘客皆清空才標記道路總排隊改善；第一個綠格不是精確門檻或最適方案。總量改善也可能伴隨某通道惡化。年圖對未清空的點不連線，不能把缺點當零。

預設人工示例：尖峰私車使用者 10,000 人、既有公車乘客 2,000 人，70% 私車使用者走主通道，平均 1.3 人／車；三條車道施工占一條，BRT 再占一條；主通道 50% 轉乘。120 人額定、85% 可用、2 分班距。BRT 約需 32 輛出勤＋4 輛備車，約可提供 3,060 人／時／方向。這些是示例輸入的算術結果，不是內湖所需車數。

執行 `node scripts/run_brt.mjs` 可重現 [示例結果](../data/simulation/brt-experiment.json)。頁面下載可保存實際所選型態、來源校驗、假設、各情境、轉乘掃描與年度結果。

## 要變成內湖的可信評估，下一步要取得什麼

1. 候選走廊實際路寬、車道與路口轉向配置、施工分期占道、專用道連續性、站點可用空間與超車可能性。不能先畫一條假路線再聲稱可施工。
2. 全年 VD 的資料定義、車種、方向、時間涵蓋，搭配車速、旅行時間、道路排隊長度、號誌相位與飽和流率。分別驗證晴雨、月份、學期、平假日與事故，保留缺測。
3. 公車逐站上下車、車內負載、實際班距與循環分布；私車載客、起訖、停車成本、轉乘意願。另檢查捷運轉乘站與列車剩餘容量。
4. 以 SUMO／其他微觀模擬建立真實路網、公交與號誌，校正到達率、轉向與回堵，再用未參與校正的日期驗證旅行時間及排隊。測試完整 BRT、混流優先、專用道＋路口改善與分批上班，對需求、轉乘及占道做敏感度／不確定性分析。
5. 若有試辦，採對照走廊與介入前後差異（例如差異中的差異），控制天氣、假日、事故與施工，量測人流通過量、全程時間、道路與候車隊列、外圍外溢及可靠度。單純前後車速比較不足以證明 BRT 的因果減塞效果。
