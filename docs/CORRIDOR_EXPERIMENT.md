# E1：國道—內湖匝道—市區的尖峰瓶頸觀測

[互動熱圖與地圖](https://clarencechien.github.io/tpethon/corridor.html) · [本次結果與來源校驗碼](../data/simulation/corridor-experiment.json) · [重現程式](../scripts/corridor_experiment.py)

這次**已執行資料擷取、相鄰跡象與跨日重複篩選、門檻敏感度分析**。不是封路／單行／BRT 的政策模擬，也不是已校正的因果研究。

## 問題與設計

想驗證的線索是：尖峰低速是否反覆出現在相同位置？下游變慢後，上游是否也較晚出現跡象？若有，再調查路口、匝道儀控及實際排隊；不能只憑車速排名決定封路。

- 固定日期：2026-10-14、10-15 上班與下班，以及 10-16 上班，共 5 個時窗。
- 上班 07:00–09:30、下班 17:00–19:30，兩端均包含；國道每 5 分鐘一筆，市區每 15 分鐘一筆。都是快照，不是區間平均。
- 固定範圍：國道 1 號 VD 代碼里程 12–22 公里，主線 M 及入口 I／出口 O；排除其他代碼，不聲稱覆蓋所有車道。三天每日靜態檔共選出相同的 25 個方向別測點。排序使用官方 LocationMile，不能用 VDID 內的舊里程取代。
- 市區取現有歷史檔中，路名含堤頂、環東、成功、民權、成美、麥帥、陽光、新明、港墘、瑞光的測點。10/14 有 82 個、10/15 有 84 個；並非這些道路的完整覆蓋。10/16 晨間市區資料尚缺。
- 不把匝道和市區測點任意連成一條道路；目前尚未確認完整拓撲與轉向。

## 結果一：成功路南向入口值得優先調查

`VD-N1-S-16-I-WS-1-內湖-成功路` 在 10/14、10/15 下班時段，都從 **17:15** 首次觀察到相鄰低速＋高占有率快照。

- 判定條件：匝道有效車速 <20 km/h、占有率 ≥25%，相鄰兩筆以上。
- 10/14 最長相鄰組 19 筆，首末相隔 90 分鐘；10/15 為 12 筆，相隔 55 分鐘。這不是實際連續排隊時長。
- 匝道速度門檻收緊至 <15 km/h，仍在兩日重複出現。
- 待查原因包括匝道儀控、下游主線壓力、設備與車道情況。**尚不能區分原因，更不能解讀為此處應封閉。**

## 結果三：市區重複候選與門檻敏感度

基準門檻下共 14 組「方向別測點 × 上／下班時段」在至少兩天重複出現：南向主線 6 組、北向 1 組、匝道 2 組、市區 5 組；不是 14 個互不重複的地點，也不是依交通損失排序。

市區為：新明路東北向 VMSV820 上班／下班、陽光街東向 VQZTP20 上班／下班、堤頂大道南向 VRHT640 下班。兩天的證據不足以證明季節性或排除紅燈與設備偏差。

| 車速門檻（主線／其他） | 重複候選組數 | 說明 |
| --- | ---: | --- |
| <30／<15 km/h | 8 | 較嚴格低速條件 |
| <40／<20 km/h | 14 | 基準 |
| <50／<25 km/h | 21 | 較寬鬆條件 |

三組占有率都要求 ≥25%，有效率都至少八成，至少兩個同類尖峰日重複。這是觀測篩選敏感度，不是道路容量變動、政策效益範圍或信賴區間。基準與較嚴格條件皆出現的成功路入口，可優先做現場與號誌查核；不能因此跳過原因驗證。

## 方法與保護條件

1. 國道對每個目標時點請求下一分鐘的 VDLive 檔，逐筆檢查 DataCollectTime；與目標相差超過 90 秒、設備 Status 非 0 均無效。來源網址、擷取時間、原檔 SHA-256、大小保留。
2. 以 VDID＋LinkID 精確連結當日靜態名冊；不同方向不混用。車速採有效活動車道算術平均，0–200 km/h 以外或非有限數排除。車道須有有效正流量或正占有率，空車道零車速不能當塞車；有占有率的靜止車列可保留零速。
3. 占有率只使用 0–100 的有效值，取有效車道平均。不是空間密度，也不是道路占用面積。沒有推估旅次數、通勤人數或容量。
4. 市區歷史檔已是 15 分鐘抽樣，只以原本應採樣的 11 個時點計算涵蓋率。中間 5、10 分鐘欄位標為未抽樣，不插值。市區未用國道補值。
5. 候選須同時低速＋高占有率，且至少兩筆相鄰快照；缺測、低占有率、重複或倒退時間都中斷相鄰組。時間間距不能大於預定間隔＋90 秒。最長組僅報告筆數及首末相隔時間，不積分成持續塞車分鐘。
6. 跨日只比相同 VDID＋LinkID、相同上／下班類別；當日有效筆數至少達預定八成，且至少兩日符合相鄰條件才列重複候選。只有三天，不做顯著性或全年代表性宣稱。
7. 主線、匝道、市區採樣頻率與門檻不同，不以低速百分比判定誰更嚴重。不把測站排序的等距列畫成真實距離。

## 重現與驗證

```bash
# 第一次取得本實驗固定日期；不需 TDX 金鑰（市區沿用已提交歷史檔）
python scripts/corridor_experiment.py --download
# 使用原始快取，檢查校驗碼並重建分析；不連網
python scripts/corridor_experiment.py
python -m unittest tests.test_corridor_experiment -v
python scripts/build_pages.py --history
# 頁面由本機既有的 8001 服務提供時
python tests/corridor_pages_smoke.py
```

重現時使用本次 Git 提交的程式與 `data/history/`，避免日後滾動保存或補回 10/16 市區資料改變輸入。原始檔若由上游修訂，先另存新版本再比較校驗碼，不直接覆蓋既有實驗證據。此實驗是固定日期的可重現研究快照；既有即時／半日排程未改成自動重跑本實驗。

測試涵蓋空車道、停滯車列、負值／NaN、過期資料、錯方向連結、缺測中斷、左設限、門檻邊界、日期時段、官方里程與市區採樣分母；瀏覽器驗證熱圖選點與地圖、時間切換、市區缺測、敏感度、手機版與資料讀取失敗。

## 接下來可以真正改什麼？

優先查成功路南向入口與南向下游主線的時制／匝道儀控、車道、排隊及旅行時間，另針對市區候選進行轉向量調查。擴大至連續數週並控制雨量、事故與施工，再挑具有可驗證路網與起訖需求的走廊。通過現況驗證後，才比較禁左轉、單行、封閉、BRT／公車優先與錯峰。

相關方法閱讀：[SUMO 動態指派](https://sumo.dlr.de/docs/Demand/Dynamic_User_Assignment.html)、[單向／雙向路網研究](https://doi.org/10.3141/2301-09)。這些是下一階段方法入口；本次 E1 為本站明列的觀測規則，未宣稱重現上述論文或已有政策效果。
