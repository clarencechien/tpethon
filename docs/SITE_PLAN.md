# E6：起終站、停靠與基地候選方案

先做港墘單線，西湖列第二階段。這份方案可供現勘、洽租與跨單位討論，尚不可直接開行。官方資料支持站牌位置與登載容量；本案可租車位、停靠權、基地入口、合法折返與司機休息設施均未確認。本次未聯繫業者或代為申請。

行善五／六場全名均為168停車聯盟。以上可租數、入口、車長重量限制與休息設施均待確認。洲子立體停車場TPE0654、內湖運動中心TPE0627、瑞光二平面停車場TPE0442都登載大型車0位，本輪排除；小客車位與平面空地不等於公車基地。

`available_bays=null` 表示未知，`contracted_bays=0` 表示本研究未確認取得配額，不表示現場無空位。坐標是官方資料點，不是入口或地界。有停車位也不等於有司機廁所、休息室、用餐空間或合規班表。

## 3. 接續道路

| 接續段 | 直線距離 | OSRM汽車路由 | 必須核對 |
| --- | ---: | ---: | --- |
| 去程時報廣場→行善六場 | 約715公尺 | 約1,088公尺 | 真正入口、限高限重、進場轉彎與排隊空間 |
| 行善六場→回程時報廣場 | 約686公尺 | 約1,360公尺 | 出場方向、回程接續、行人衝突 |
| 港墘回程站→起站 | 約154公尺 | 約984公尺 | 站牌離站方向、合法繞行，不假定原地迴轉 |
| 西湖回程站→起站 | 約25公尺 | 約85公尺 | 短汽車路由也不代表公車可迴轉 |

OSRM使用`driving`汽車模型，未限制起終點車頭方向；基地資料點吸附到附近道路約13公尺，不代表入口。沒有驗證大客車車長、轉彎半徑、道路許可或限高限重。地圖預設關閉，勾選後以橘色點線供現勘參考。導航秒數未用來校正尖峰車程。

開放網域後，OSRM成功；停車查詢站仍403、公車網站503、Overpass逾時，因此入口圖與道路限制尚未查全。搜尋跳轉頁不作研究證據。

## 4. 車輛、班距與場地

需求來源為**2026年9月22個週一至週五**捷運OD人次（未排除假日），選所屬目的站、來源進站07:00–10:00旅次，假設30分鐘後抵達，並非今日實際候車人數。先假設其中5%搭此接駁，港墘平均504人／晨、西湖437人／晨；目的地與搭乘意願尚未確認，也未扣除企業既有接駁。不是5%汽車轉乘，不能換算減塞百分比。

| 資源 | 港墘單線草案 |
| --- | --- |
| 車隊／班距 | 9輛出勤上限＋1輛備車，每6分鐘一班 |
| 服務窗 | 抵達07:30–10:30，追蹤至11:30，假設預先調度就位 |
| 上下客 | 起站洽准1個獨立上客位，時間假設2分鐘；四個下客站的停靠權與容量待查 |
| 營運中基地 | 2個休息候發位＋1備車位，休息假設10分鐘 |
| 開收班 | 確認10格；同一批車位分時使用，不再加2格和1格 |
| 車程 | 一圈行駛及沿途停靠30分鐘，另加基地往返10分鐘，均非實測 |
| 停車預算 | 15,000元×10格＝150,000元／月，非報價，不含車、人力、燃料或設施 |

基準假設下22/22天通過，最不利日期及到站偏移的離站等待P95為7.5分鐘。7出勤＋1備車也能通過基準，但基地往返增至20分鐘後0/22通過；9＋1在此情境仍22/22通過。若一圈增至45分鐘、基地往返20分鐘，9＋1也0/22通過；需求比例增至10%時港墘僅2/22通過。必須先量測車程與需求，不能因總車位足夠就採購。

兩線若同時採9＋1，共20輛、開收班20格；營運中分別保留休息候發位、合計最多4格及2輛備車位。模型獨立運算，未證明共用入口、車道和調度可承受兩線疊加。

本輪是單線5%假設需求，與前輪44輛的需求比例和模型不同，不能比較為同樣服務只需10輛。

## 5. 現勘與洽談清單

| 對象 | 要取得的資料 | 通過條件 |
| --- | --- | --- |
| 停車場／停管單位 | 入口、核准車種、10格租用期間與價格、場內配置 | 書面可用配額及配置，不只總位數 |
| 公運／交工單位 | 起站及四個下客點使用許可、接續道路與行人動線 | 方向別大客車可行路線與停靠配置 |
| 公車業者 | 車輛、司機、休息室廁所、班表、尖峰實跑 | 實測上下客／行駛／空駛分布及休息確認 |
| 企業 | 匿名目的地、上班時間、轉乘意願、現有接駁 | 可估本線需求，避免重複計算 |
| 試辦單位 | 多日期候車、未搭上人數、準點率及駕駛休息 | 實測更新模型後決定是否擴張西湖線 |

下一個實驗應加入實測車程分布、基地入口排隊與兩線共用基地；取得道路和OD資料後，再建封路、單向化或BRT車道路網分派模型。本輪未模擬道路容量變化，未證明壅塞下降。

## 6. 來源、方法與重現

1. [臺北市停車場基本資料](https://tcgbusfs.blob.core.windows.net/blobtcmsv/TCMSV_alldesc.json)：地址、總位、服務時間、費率、TWD97資料點；保存原始檔SHA-256、更新及取得時間。
2. [臺北市公車基本資料](https://tcgbusfs.blob.core.windows.net/blobbus/GetRoute.gz)：藍26業者為三重客運；「東南客運停車場」站名不證明藍26基地使用權。紅3記載平常日停駛，不列為本案晨間現成供給。
3. [TDX StopOfRoute](https://tdx.transportdata.tw/api/basic/v2/Bus/StopOfRoute/City/Taipei?%24top=10000&%24format=JSON)及`route-candidates.json`方向別站點與主線參考線形。按最近頂點截線，檢查起終順序與150公尺偏移門檻；不作新線合法性認證。
4. [OSRM](https://router.project-osrm.org/)及[OpenStreetMap](https://www.openstreetmap.org/copyright)：汽車路由與底圖；完整路由URL、SHA-256、取得時間在`site-plan.json`各段`car_reference.source`。
5. [需求資料](../data/simulation/service-inputs.json)、[E2服務模型](SERVICE_EXPERIMENTS.md)、[E4車隊](FLEET_EXPERIMENTS.md)、[E5場地](SPACE_EXPERIMENTS.md)、[BRT研究引用](BRT_TRANSITION.md)。本輪沿用E5，沒有新增因果減塞結論；BRT研究不能證明這條接駁線的減塞百分比。

坐標用pyproj 3.7.2由EPSG:3826轉EPSG:4326、`always_xy=True`。模型搜尋半分鐘班距，限制車隊、上客位與休息候發位；FIFO排隊、6分鐘集中到站、測12種偏移。等待含上下客，通過須已離站者P95≤10分鐘且11:30前無未離站者。預先配置的循環不模擬開收班調度，故另列全車隊停車需求。未包含各下客站容量、道路回堵、缺勤、午後服務或完整駕駛工時合規。

`site-service.json`保留需求、場地及模型SHA-256。重跑方式（一般網站與CI不需要pyproj）：

```sh
python scripts/fetch_site_plan.py
python -m venv /tmp/neihu-sites-venv
/tmp/neihu-sites-venv/bin/pip install pyproj==3.7.2
/tmp/neihu-sites-venv/bin/python scripts/prepare_site_plan.py
# 可選，一般汽車路由，不作大客車認證
python scripts/fetch_site_plan.py --roads
/tmp/neihu-sites-venv/bin/python scripts/prepare_site_plan.py
node scripts/run_site_plan.mjs
python -m unittest discover -s tests -v
node --test tests/*.test.mjs
python scripts/build_pages.py --history
```

HTTPS採預設TLS驗證；原始快取在忽略的`local-data/sites/`，預設重用校驗正確的快取。更新時先備份再移除欲更新的`.raw`及`.evidence.json`配對，重新執行並審查來源欄位與結果。API可變，新抓資料未必重現舊快照；Git保存候選坐標、來源校驗碼與情境結果，沒有公開金鑰。
