# E7：轉乘 hub、停車補助、共乘與尖峰管制

查核及實驗日期：2026-10-17（台北時間）。[互動頁](https://clarencechien.github.io/tpethon/hubs.html)｜[閱讀路徑](https://clarencechien.github.io/tpethon/experiments.html)

這是可重跑、具容量與預算限制的合成旅次實驗，不是內湖政策預測。目的是找出需要查證的條件、容量瓶頸和可能反效果。沒有啟動交通管制、預約停車、發放補助或開發獎勵App。

## 問題與目前可支持的結論

把低乘載車輛留在外圍，可能增加公共運輸的人流通過量；但若車位不足、轉乘太慢、巴士不足或管制後集中放行，也可能增加全體旅行時間。第一輪刻意保留這些反例，不把被擋住的人刪除。

同一批6,000名原本單人開車的合成旅客，六個政策情境如下。數字僅為種子7的指定假設結果，**不是內湖實測人數、最適hub排名或可承諾的改善幅度**。

| 情境 | 本批需進區私車 | 07–10時已進區私車 | 因管制延後人數 | 已完成人平均耗時 |
| --- | ---: | ---: | ---: | ---: |
| 全部單人開車 | 6,000 | 3,561 | 0 | 78.3分 |
| 花博＋機場轉乘 | 5,879 | 3,466 | 0 | 77.8分 |
| 六個市區hub | 5,506 | 3,419 | 0 | 73.1分 |
| 六個hub＋共乘補助 | 4,837 | 3,195 | 0 | 69.4分 |
| 同上＋3人高乘載管制 | 4,837 | 476 | 3,387 | 130.6分 |
| 再加假設600人區域鐵路接駁配額 | 4,322 | 454 | 2,992 | 119.0分 |

主要反例：高乘載管制沒有再降低本批需進區私車總數，只把大量低乘載旅客延後，尖峰車少但旅行時間變長。模型的行為選擇沒有因管制改變，所以這是「有人不改運具，只願意等解除」的壓力情境，不是預測真實民眾一定如此反應。

另跑144組：停車配額10／30%、停車補助0／150／300元、App參與30／70%、無管制／3人門檻、一般道路容量100／70%，各3個隨機種子。這是條件範圍，不是信賴區間、機率預測或完成所有參數的全域最佳化。第三層與各hub組合可在頁面另試，未宣稱已窮舉全部子集合。

## 三、模型與所有重要假設

### 合成人員與時間

預設6,000個原本單人開車者，來源區台北西側、台北南側、新北西側、新北南側、汐止、基隆、桃園、內湖東側，各等權重1/8。這是設計假設，不是抽樣估計。每人一個唯一ID，固定種子產生出發時間、App參與、共乘及選擇偏好。出發時間為兩個均勻亂數之和乘90，涵蓋07:00–10:00，並非由VD推回的到達需求。所有方案使用同一批人。

只追蹤晨間單程到16:00；補助按每車全日一次計算，不代表已模擬下午回程。未包含原搭公共運輸者轉開車、機車、旅次取消、企業錯峰或新誘發旅次，因此不能當全體通勤評估。

### 空間、車程與選擇

- 地圖只顯示點；模型距離＝球面直線距離×1.4，非道路路由。私車及hub接近速度假設25km/h，直接行車另加10分鐘；hub接近另加5分鐘；BRT單程為代理距離／25km/h＋8分鐘沿途停靠，步行轉乘另4分鐘。
- 鐵路／公路接近速度假設35km/h、接近與候車另12分鐘；只有第三層啟用合計名額，來源區索引2–6的部分人可參與。不聲稱任何車站實際有600空位，也不把鐵路列車容量當停車位。
- 選擇預期：直接開車成本＝直接時間＋預期道路延誤15分＋目的地停車200元／時間價值5元每分。轉乘成本＝接近＋BRT＋步行＋半個班距＋淨票價／停車費換算時間。停車費統一400元、BRT40元；鐵路接近另60元。全部是假設，不是來源場地的自動報價。
- 轉乘機率為 `1/(1+exp((轉乘成本−開車成本)/10))`。分母10分鐘是未校正的偏好分散參數。只有App參與者進入此選擇，尚未模擬非App旅客獨立轉乘。
- 有車位資訊時，按成本依序找仍有配額且補助預算可支付的hub；無資訊時只試第一個hub。這是對hub分配的資訊實驗，不是實際道路導航，也沒有做路網均衡或動態壅塞反饋。

### 共乘、補助與管制

先配共乘，再處理剩餘人的轉乘選擇，結果受此順序影響。共乘限同來源區、同目的地、同15分鐘出發窗。無管制時以3人一車測試；2／3人高乘載時採對應群組大小。每車一名駕駛，其餘為乘客，未湊滿者保留原旅次。

共乘參與門檻假設為 `min(補助,120)/300`，再受App參與率限制；這個函數**沒有實證校正**，不代表補助100元就能讓三分之一人共乘。每成功群組補助不超過假設燃料支出120元，並計每車而非每人；繞行代理距離增加15%、行車時間另加8分鐘，等候同組最晚出發者。停車補助不超過假設停車費，按已分配的車位支付，轉乘點數沒有再重複兌現為額外預算。總預算硬限制，順序先共乘後停車，不是最佳化預算配置。

管制只作用於單人車、原預計10:00前到關口者；5%特殊通行比例為假設。其餘無法轉乘者延期到10:00後0–15分到達關口，之後仍要排隊。**沒有把禁入人數當成旅次消失，也沒有假設管制會自動提高轉乘意願。** 未實作2人車違反3人門檻等既有車隊組成，因基準只有單人車及模型成功配對車。

### 運能與排隊

- 6個關口為點排隊，各自設定假設每小時容量：民權500、環東450、成美350、成功400、南湖300、麥帥300，非實測值。沒有有限儲車空間、號誌、道路回堵、交叉口與外圍改道。可將一般道路容量縮為70／50%測占道不利影響，但不是實際施工配置。
- 私車來源區及hub接續到關口的關係是規劃假設，非合法道路路由；BRT假設有獨立路權，未進入一般車點排隊，因此結果中的車數一律指私車，不含BRT。
- 巴士採固定班距、先到先上、每班有限容量。每hub出勤車數＝`ceil((2×單程時間＋12分折返休息)/班距)`；另加向上取整10%備車，不把備車放入常態班表。這是配置需求，不是可用車隊證明；未核對站台、基地、駕駛班表或勞動合規。
- 車位全日占用，模型不回收；巴士各站未完成乘客與關口尚未完成旅客保留。平均與P95只對已完成者計算，必須連同未完成數讀取。

## 四、實地驗證與App設計

1. **基線期**：至少涵蓋多個正常工作週、天氣及活動日，取得企業匿名來源區／上班時段／原運具／乘員數；量測關口車種、乘載率、旅行時間、停車占用及公車候車。年度資料可後續擴充，不能以多日期取代缺失的OD。
2. **優惠拆組**：以企業或來源區分組，避免同一共乘團隊被拆到不同組。比較資訊指引、資訊＋停車補助、資訊＋共乘補助、同額補助＋遊戲化；預先訂主要指標、最小可偵測效果，再用基線變異與群聚相關計算樣本量，不先捏造需要幾百人。
3. **按分派評估**：保留未接受優惠者，以原分組作意向治療比較。記錄拒絕與退出原因；補助停止後觀察是否持續。需要主管機關核准的交通管制，放在大眾運輸與場地可行性確認後的獨立階段，不與遊戲化效果混算。
4. **驗證完成旅程**：在同意下，用停車／乘車憑證與當日匿名配對代碼核實轉乘；共乘用同車同行時窗、到達與乘員去重檢核。不能僅GPS打卡領取共乘油錢。資料最小化並訂保存期間；本輪未蒐集個資或建置此系統。
5. **App指引**：先提供剩餘配額、預約、候車、可替代hub與到班時間；真實導航須使用核對過的道路與車種限制，避免把分流導入住宅巷道。點數依完成轉乘／共乘核發，分清原搭公共運輸者與新增轉乘，不靠里程增加獎勵。
6. **整體結果**：門到門時間、準點／晚到、未載完、交通可及性、車公里、外圍回堵、管制解除車潮、補助與營運成本；分原運具、出發區及收入等可取得分組分析。另招募／觀察原公共運輸使用者，檢查停車補助誘發開車的反效果。
