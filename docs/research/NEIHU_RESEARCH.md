# 內湖交通：資料盤點、分析方法與改善試辦

研究日期：2026-10-16（臺北時間）。本報告區分已取得的實測資料、已讀取的技術文件，以及尚待核對的文獻線索。沒有把模擬結果或外地成效套成內湖的改善幅度。

## 結論與優先順序

建議先做三件事：**建立有方向的聯外走廊基準、改善公車可靠度與捷運最後一哩、用企業分組試辦驗證錯峰上班**。先不要用「路線和捷運重疊」直接刪公車，也不要用到站預估代替乘客需求。DRT 適合在確認低密度、分散需求後試辦，不宜先拿來替代晨尖峰高需求幹線。

現有資料足以做監測、旅次來源分群與試辦設計，但還不足以估算「彈性工時一定能省幾分鐘」或「需要減少幾輛公車」。缺口主要是完整晨尖峰歷史、實測旅行時間、乘載率／站點上下車量、號誌與企業通勤時間資料。

## 三、分析方法：從監測到可驗證的政策

### 1. 聯外走廊斷面與瓶頸診斷

先定義「進入研究區域」的邊界與道路方向；每條穿越邊界的獨立車道只能計一次。以成美橋、民權大橋、堤頂大道、麥帥／環東等聯外走廊為候選，人工核對橋面、匝道、平面道路與重複感測位置。

已輸出 [cordon_candidates.csv](cordon_candidates.csv)，但全部標為 **未審核**，不可直接求和為入區流量。當前靜態資料用道路名稱搜尋找不到「成美」不代表成美橋無感測器；可能有不同命名或其他主管機關來源。必須用座標與 LinkID 核對。

對每個「VD × LinkID × LaneID × DataCollectTime」保留一筆觀測，Status 異常者保留但不算有效速度。依確認後的原始統計區間組成 15 分鐘窗，附觀測覆蓋率與缺漏標記，不把缺值補零，不把每次重抓同一快照累加。

建議圖表：方向別流量—車速—占有率、沿走廊的時間—位置速度圖、排隊出現時間及向上游延伸順序。占有率只是密度代理，未校正有效車長前不能直接當 vehicles/km。低速同時低流量可能是堵塞、紅燈、故障或空車道，需觀察鄰近 VD 與 CCTV。

**Macroscopic Fundamental Diagram（MFD）** 可作為較後期的區域壅塞分析：檢查網路累積車輛與完成交通量之關係。但現在樣本分布不均、缺道路長度及完整進出邊界，不宜把目前的點速度平均稱為內湖 MFD。

### 2. 旅行時間可靠度，而非只看平均速度

公車 GPS 累積後，依路線／方向／車輛旅次做 map matching，估算固定站間或走廊端點的實測旅行時間。車輛 ID 不等於乘客 ID；發表報告只輸出彙整，不推測駕駛個人行為。

指標：中位數、P90/P95 旅行時間、準點率、實際班距及班距變異、等待時間、末班可靠度。若有可合理定義的自由流旅行時間，可報 Planning Time Index = P95 旅行時間 / 自由流旅行時間。不能把單個 VD 點速度反推成整段實測旅行時間。

對乘客隨機到站、且沒有滿載上不了車的高頻服務，期望等車時間可用 `E[H²] / (2 E[H])` 評估班距不穩定代價；預約班次、低頻時刻表服務和有拒載情形不適用此簡化假設。

### 3. 公車與捷運的功能分工

先將實體站點、路線方向、路線軌跡、捷運站出入口與步行路網整合。接駁可及性用步行路網及過街成本，不只畫直線半徑。路線重疊率只能當篩選指標，還需檢查直達需求、轉乘負擔、無障礙、最早／最晚班與保底服務。

用站點上下車/APC、匿名刷卡聚合或企業通勤調查判斷需求；目前公開 GPS／ETA 都不能取代它們。駕駛班表需另納入法定／契約休息、實際回復時間、調度站空間、廁所及空駛，不預設特定法規分鐘數。

### 4. 錯峰上班：用實驗評估，避免把相關性當因果

建議先收集至少 4–8 週完整基準，再挑選有意願且工作型態相近的企業或部門。以公司／部門為分組單位，採隨機分階段導入（若可行），或匹配對照組與 Difference-in-Differences／event study。

紀錄實際到班時間、通勤方式、匿名起點區域、可接受提前／延後範圍及營運 KPI。分清「允許彈性」與「員工實際改變出發時間」。配對日期需控制星期、雨量、假日／補班、學校作息、事故、工程與特別活動；檢查平行趨勢及跨公司／跨道路外溢。

主要結果：每人通勤時間、P95 遲到風險、尖峰寬度、路廊延誤、搭乘公共運輸的比例與企業營運指標。觀測窗延伸到 06–11 時，避免只把 08 時擁堵移到 09:30 以後就宣布成功。以意向治療效果與實際參與率分開報告，做分組層級的不確定性估計。

### 5. 規劃情境與模擬

先建小範圍、可校正的模型，再加入 Plan。可設 5%、10%、20% 的候選出發需求提前／延後 15 或 30 分鐘作為**敏感度假設**；不是內湖參與率預測。假設模型保留總旅次與可移動的人群限制，重算路徑、排隊、轉乘及公車延誤。

SUMO 可模擬多運具、路口號誌、公車優先與 DRT。需取得車道拓撲、轉向比例、號誌時制、需求及服務班表，用一組日子校正，另一組未參與校正的日子驗證。避免將模擬器的強制流量校正（會插入或移除車輛）當成改善政策本身，或在反事實情境中強制維持基準結果。

至少對照：現況、僅錯峰、僅公車優先／接駁、組合方案。衡量**人時延誤**、可靠度、等待／轉乘、空駛與駕駛工時，不只汽車平均速度。沒有完整輸入前不發布「可節省 X 分鐘」估計。

## 六、尚缺的資料與精確下一步

1. **完整歷史**：目前只有兩次 VD 採樣，不能研究整個晨尖峰。建議一開始先累積 4–8 週，含 06–11 時以及必要對照時段。先確認源端統計時間窗，再定義 15 分鐘完整性門檻。
2. **國道／快速道路聯外**：尚未成功讀取 `tisvcloud.freeway.gov.tw`，需驗證其實際目錄、VD 與 ETC M03A/M05A/M06A 欄位、更新方式與授權，不能先假設這些產品等於內湖完整 OD。TDX 選項需另驗證所需 API 的帳號權限。
3. **公車需求**：匿名站點上下車量、APC、滿載／拒載、時刻表及發車紀錄；與業者討論資料粒度與品質。未取得前不宣稱找到「冷站」。
4. **捷運供給**：列車班距、編組容量、實際站台／列車乘載與轉乘分布，才能討論能否承接道路轉移需求。
5. **路網與號誌**：LinkID 對應路段、長度、限速、轉向、匝道、時制計畫、行人時相與工程／事故。
6. **日曆、天氣與活動**：臺灣辦公日曆、逐時降雨、學期／補班／大型活動，避免將假日或雨天效果誤判為政策效果。
