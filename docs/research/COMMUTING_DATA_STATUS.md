## 下一份資料要回答什麼

優先找普查的「居住地 × 工作地」交叉表，先核對定義與地域層級，再決定能用在哪一層。以下是查找條件，不是宣稱已確認存在這些公開表格。

| 優先資料 | 可以支持的分析 | 還不能推論的事情 |
| --- | --- | --- |
| 各居住區 → 內湖工作區的就業人口 | 校正來源分布；比較基隆、汐止、新北西側等接駁方向 | 不一定每天通勤；不等於晨尖峰私車人數 |
| 若只有縣市 → 縣市交叉表 | 限制跨縣市流動總量，作較粗的背景或敏感度條件 | 不能把前往臺北市的人全部分給內湖，也不能直接排名橋梁 hub |
| 通勤運具、出發／到達時段、每週到班日數 | 從就業人口逐步建立晨間旅次，再分私車、機車及公共運輸 | 若只有各欄位的總分布，不能假裝知道它們之間的聯合分布 |
| 匿名企業通勤調查：來源區、工作點、運具、時段、乘員數 | 校正本案合成人員；區分可共乘與可能轉乘者 | 企業樣本仍有涵蓋及自願參與偏差，不能直接代表全區 |
| hub 可租車位、進出量、班次剩餘運能與實測車程 | 檢查需求能否被停車與運輸容量承接 | 停車場總位不是可租配額；車站總進出量不是剩餘運能 |

## 取得資料後怎麼用

1. 保留原始下載網址、資料年月、定義、單位、地域代碼及檔案校驗碼；檢查區域加總是否吻合總表。
2. 把人數、旅次與車次分開。普查工作地不一定是每天實際出勤地；入區車輛也可能是過境或非通勤，不能直接互換。
3. 如果取得的是 2020 年普查，只建立「2020 年結構參考」情境。與 2026 年戶籍人口的差異不能只乘一個成長率，就宣稱得到目前內湖通勤量。
4. 有足夠交叉表與種子樣本後，再評估加權或 IPF 校正。保留既有等權重情境比較敏感度；不只公布最有利的來源分布。
5. 用未參與校正的日期或企業樣本驗證。比較全程時間、未完成旅次、實際私車總數及管制解除後車潮，不只看 07–10 時少了多少車。

資料未補齊前仍可做容量壓力測試，例如「只有 100 格可租車位」、「部分班次客滿」或「不願轉乘者等到解除管制」。這能找出失敗條件，但還不能承諾真實減塞百分比或選出最佳 hub。
