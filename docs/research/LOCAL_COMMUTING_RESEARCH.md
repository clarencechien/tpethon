# 找到了什麼在地證據？

查核日期：2026-10-17。這輪沿臺北資料大平臺新版介面的公開搜尋API取得三份完整PDF及一份廠商CSV，閱讀下列指定段落；**未宣稱讀完全部報告**。原檔留在本地快取，Git保存小型[來源清單與校驗碼](../../data/simulation/hub-local-research.json)。

## 1. 有內科員工來源分布，但引用的是2005年調查

[《臺北市科技軸帶交通發展計畫（第一期）》](https://data.taipei/dataset/detail?id=25986a31-7e9f-45b2-8347-d047092295f5)，臺北市政府交通局委託、財團法人臺北市交通文教基金會執行。封面為**2012年8月**；平臺「年度」欄100不是封面出版日期。

- PDF第164–166頁／正文2-104至2-106，表2.47及圖2.32引用《內湖科技園區交通總體檢計畫報告（2005）》：臺北市55.66%、新北市36.69%、基隆地區4.43%、桃園地區3.22%。不能標成2012年或2026年實測。
- 原表列內湖18.01%、汐止6.40%、士林6.13%、板橋4.84%等。已目視核對PDF：臺北市細項加總55.68%，與小計55.66%差0.02個百分點；新北市細項合計36.46%，與小計36.69%差0.23個百分點。未自行補差或正規化。
- 尚未取得2005年原始報告與樣本設計，不能確認樣本數、抽樣權重、未回覆與涵蓋範圍。這是**歷史二手引用**，沒有現代完整OD或絕對通勤人數。
- PDF第166–168頁／正文2-106至2-108另引用《99年度內科員工旅次特性調查分析》（2010），包含運具與旅行時間、共乘及停車地點。表2.48只列各時間類別最高與次高運具，不能當完整運具分配；表2.49的「共乘人數」定義與調查單位尚待原調查核實，不直接推成平均車輛乘載率。

**對方案的啟發：** 歷史資料提醒我們不能只討論長途跨縣市BRT，還要查內湖、汐止等近距離旅次的機車、步行與接駁需求。但現在的需求、路網與就業分布可能已改變，不能據此設定目前各橋的流量。

## 2. 停車轉乘優惠與個人化交通資訊，臺北已有研究

[《臺北市建立交通機動力服務中心可行性評估》](https://data.taipei/dataset/detail?id=2835bbfa-ee24-4f2c-97ca-234846389db8)，2009年12月，臺北市交通局委託、中華智慧型運輸系統協會執行。

- PDF第180、184頁／正文166、170：2009年10月1–8日針對臺北市18歲以上居民進行電話調查，成功1,805份；採行政區、性別、年齡的Raking加權。這不是內湖員工專屬樣本。
- PDF第191頁／正文177：問卷討論公車＋捷運與停車轉乘優惠組合。需求意願不能直接當實際參與率。
- PDF第228頁／正文214，表6-8：討論停車期間搭乘公共運輸可享公有停車場5折優惠；評估從知曉、購買、使用意願，到持續購買、公共運輸運量、停車場利用及道路服務水準。
- PDF第238頁／正文224，表6-13的效果屬問卷推估及樂觀／保守預期，**不是政策實施後的因果驗證**；本案沒有採用其轉移係數或改善百分比。

**對實驗的改進：** 除「多少人領點數」，還需量測是否真的換運具、是否持續使用、原公共運輸者有沒有改開車到hub。停車補助應與已完成的乘車行程連結，並把停車配額、營運費與驗證成本一起評估。

## 3. 交通民意調查可參考問法，但不能代表當前內湖

[《107年第1次（5月）臺北市交通民意調查報告》](https://data.taipei/dataset/detail?id=e8600a47-0788-414e-af8e-c065444b07aa)，2018年5月20–27日，交通局委託艾普羅民意調查股份有限公司。

已讀PDF第3–6頁摘要：市話有效樣本1,080份，對象為臺北市15歲以上居民；手機樣本555份，包含364份臺北市居民及191份外縣市通勤（學）者。兩種抽樣母體不同，不能直接拼成內湖的模式比例。摘要涵蓋通勤時間、費用、運具、資訊使用及轉乘優惠意願，可作新調查的題目參考；意願不是實際減車效果。這份政府平臺公開下載的舊報告封面另有「僅供內部參考」字樣，本案提供原始官方連結及方法摘要，不重刊整份PDF。

## 4. 取得內科廠商名錄，但沒有員工數

[《臺北市內湖科技園區廠商名錄》](https://data.taipei/dataset/detail?id=15c3e1ae-899b-466c-a536-208497e3a369) CSV列出統編、公司名稱、地址與ADDR_X／ADDR_Y。實際下載5,692列、5,692個不同統編；平臺詮釋資料的筆數卻是5,349。資源最後修改時間2026-09-03，頁面更新時間不能當作所有公司仍在場的查核日。

可用來規劃企業抽樣與目的地分區，但需核對在場企業、員工數及辦公地。**不能一家公司算同樣多人，也不能把公司數當上班人數。** 尚未對外聯絡或收集員工資料。

## 下一輪實驗的具體設計

1. **分開三種人。** 原汽車駕駛、原機車使用者、原公共運輸使用者；再依近距離／跨區來源分層。歷史表只提示哪些族群要涵蓋，現況比例以新調查估計。
2. **比較三種服務。** 維持既有捷運＋最後一段接駁、外圍停車轉BRT、來源地直達快線；同一旅客用門到門時間、費用及可用容量比較，避免強迫所有人繞到hub。
3. **先分開測優惠。** 資訊指引、停車補助、共乘補助，以及同額補助加遊戲化。記錄原分組、未使用優惠者、完成行程與數週後是否持續；總預算與車位硬限制。高乘載管制另作等待解除的壓力情境。
4. **補上反效果指標。** 原捷運客改開車到hub、接近hub的新增車公里、車位不足、停車入口排隊、錯過班次、下午回程與解除管制後車潮。現行E7尚未模擬全部項目，不把這份設計寫成已完成的效果驗證。

取得現在的分層通勤樣本及場地配額後，再校正合成人員與選擇模型。2005年分布可保留為歷史對照情境，但不與2026年人口或捷運數據相乘成「真實通勤人數」。

## 如何重查來源

臺北資料大平臺目前網頁使用 `POST https://data.taipei/api/v2/frontstage/tpeod/dataset.search`，JSON包含 `page_num`、`page_limit`、`qs`、`sort: "metadata_changed.date_desc"`。本輪查「內湖科技園區」與「通勤」，各讀取兩頁、每頁最多100筆；搜尋會包含不相關結果，不能用命中數代表研究數。每筆再以 `GET /api/frontstage/tpeod/dataset.view?id=資料集ID` 取得資源ID，透過 `/api/frontstage/tpeod/dataset/resource.download?rid=資源ID` 下載。所有資料集ID、下載網址、檔案大小、下載時間及SHA-256均記錄在來源JSON。四個檔案下載大小均與資源詮釋資料相符。
